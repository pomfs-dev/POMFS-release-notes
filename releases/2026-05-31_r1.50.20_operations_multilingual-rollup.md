# r1.50.20 - Operations

Date: 2026-05-31
Released at: 2026-05-31 21:58 KST
Component: Operations
Status: not-deployed

## Summary
POMFS의 다국어 작업 범위를 한 번에 정리했습니다. 커뮤니티 웹 active route, 알림/푸시, 기기 언어 자동 선택, iOS 언어 전달, 메일 템플릿까지 ko/en/ja/es/th 기준으로 일관된 언어 경험을 제공하도록 정리했습니다.

## Changes
- 커뮤니티 웹 active route 전반을 ko/en/ja/es/th 선택 UI 언어 기준으로 정리하고 route family 단위 smoke 범위를 확인했습니다.
- 관리자, 프로필, 검색, 정산, 티켓, 게스트리스트, 공연 관리, 채팅, QR/스캐너, 온보딩, 법적 문서 shell 등 넓은 화면군의 버튼, 탭, empty state, modal, toast/error fallback, 날짜/숫자/금액 표시를 언어 선택 기준으로 정리했습니다.
- 처음 접속하거나 앱을 사용할 때 기기 언어가 지원 언어 중 하나이면 기본 UI 언어로 자동 반영되도록 했습니다.
- 새로 생성되는 알림과 푸시 알림 문구가 사용자의 선택 언어 또는 기기 언어를 더 잘 따르도록 정리했습니다.
- iOS 앱의 푸시 등록 정보에도 기기 언어가 함께 전달되도록 소스를 준비했습니다.
- 회원가입 인증번호, 비밀번호 찾기, 가입 완료, 결제 완료, 티켓 발급 안내 메일도 사용자 언어 기준으로 발송될 수 있도록 서버 템플릿과 발송 경로를 정리했습니다.
- 이번 작업이 오래 걸린 이유는 단순 문구 치환이 아니라 모든 active route에서 하나의 선택 언어만 유지해야 했고, 로그인/관리자/결제/티켓/알림처럼 사용자 상태와 API 응답이 얽힌 흐름을 5개 언어로 각각 검증해야 했기 때문입니다.
- 사용자 생성 콘텐츠, 기존 DB 콘텐츠, 이미 저장된 알림 문구는 임의 번역하거나 backfill하지 않는 원칙을 유지했습니다.

## Known Issues
- 이미 저장된 기존 알림과 사용자 생성 콘텐츠는 변경하지 않습니다.
- 법적 문서의 본문 번역은 언어별 법무 검토 전까지 원문을 유지합니다.
- 메일 다국어 발송은 backend 배포 후 실제 수신 smoke로 최종 확인합니다.
- iOS 네이티브 런타임 검증은 full Xcode 환경에서 다음 세션에 진행합니다.
